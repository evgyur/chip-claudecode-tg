# Онбординг — Telegram Claude Cockpit

Это инструкция для ежедневной работы в Telegram Claude cockpit через OpenClaw ACP.

## Коротко
- У тебя есть отдельный Telegram-чат под Claude ACP
- Внутри есть topics
- **Один topic = одна задача / один поток работы**
- Основной control-topic — `Codex Control`
- После первичной настройки можно писать обычным текстом

## Что где делать
### `Codex Control`
Используй для:
- проверки ACP статуса
- выбора модели Claude
- первого smoke test
- управления runtime, если он подвис

### `Inbox / Triage`
Используй для:
- новых задач, которые ещё не разложены по темам
- быстрых входящих идей

### Остальные topics
Используй как отдельные рабочие зоны под проекты, инфраструктуру или эксперименты.

## Самый правильный первый запуск
1. Зайди в `Codex Control`
2. Отправь `/acp status`
3. Отправь `/acp model opus`
   - если нужен более дешёвый режим — `/acp model sonnet`
4. После этого отправь обычную задачу, например:
   - `Посмотри repo, составь короткий план и начни с безопасных правок`

## Какие команды реально нужны
### Основные
- `/acp status` — посмотреть статус ACP Claude session
- `/acp model opus` — переключить на сильную модель
- `/acp model sonnet` — переключить на более дешёвую/быструю модель
- `/acp reset` — сбросить session, если модель или runtime застряли
- `/acp cancel` — остановить текущий turn, если runtime поддерживает это поведение

## Важная оговорка про модели
Для Telegram Claude cockpit через `acpx` использовать лучше backend-native ids:
- `opus`
- `sonnet`
- `haiku`

Не считать строки вида `anthropic/claude-opus-4-6` canonical источником истины для этого контура, если реальный backend работает через `acpx` и `claude` CLI.

## Как работать без боли
1. Убедись, что `/acp status` отвечает
2. Один раз выставь нужную модель (`opus` или `sonnet`)
3. Дальше просто пишешь по-человечески
4. Для новой большой задачи открываешь отдельный topic
5. Если после смены модели runtime ведёт себя странно — сначала `/acp reset`, потом снова `/acp model ...`

## Если что-то не работает
### `/acp status` отвечает, но обычные prompts молчат
Проверь:
- что topic привязан именно к ACP Claude binding
- что `acpx` backend ready
- что Claude CLI залогинен на этом же сервере
- что команда отправлялась человеком, а не ботом самому себе

### `/acp model opus` “сработал”, но реальный backend не сменился
Лечение:
1. `/acp reset`
2. `/acp model opus`
3. заново отправить обычный prompt

### Claude CLI не залогинен
Нужно войти именно в том server/user context, где работает OpenClaw runtime. См. `preflight-checks.md`.
